The Three Fatal Flaws of Pure LLMs in Code Review

Standard developer tools either enforce rigid syntactic rules (linters) or review diffs in total isolation (naive ChatGPT prompts). CodeSense was engineered to solve three specific points of failure:

  • Context Window Blindness: A real repository contains hundreds of files. You cannot feed an entire project into an LLM on every pull request without incurring high cost ($2+/review) and 45s+ latency.
  • Private Codebase Hallucinations: Foundation models have zero knowledge of your private architectural rules or internal helper utilities (e.g. recommending raw TCP sockets instead of the repo's get_db_pool()).
  • Invalid Coordinate Errors: LLMs are probabilistic language engines that miscount diff lines, triggering fatal GitHub API HTTP 422 Unprocessable Entity errors.

Tree-Sitter AST & Reciprocal Rank Fusion

Rather than cutting code arbitrarily by line numbers (which cuts functions in half and destroys semantic meaning), Tree-Sitter constructs concrete syntax trees across 4 languages to extract complete function units.

# Reciprocal Rank Fusion (k=60) # Merges dense vector rank + sparse BM25 keyword rank def calculate_rrf(dense_rank, sparse_rank, k=60): return (1.0 / (k + dense_rank)) + (1.0 / (k + sparse_rank))

The constant k=60 (validated by Cormack et al.) prevents an outlier ranked #1 in only one engine from dominating an item that ranked #2 in both engines.

Senior Defense 01 How do you guarantee the LLM will not hallucinate invalid line numbers?
Testing: Real-world operational risks of LLM hallucinations & deterministic guardrails.
We enforce a zero-trust boundary around the model. First, temperature is set to 0.1 for deterministic decoding with a strict JSON schema. Second, in Stage 8, our Go Review Worker parses the git diff hunk headers into a hash set of added lines (+ lines). If the LLM proposes a comment on an unchanged or non-existent line, it is safely pruned before calling GitHub's API. This guarantees 100% delivery reliability and eliminates HTTP 422 errors.
Senior Defense 02 Your raw embeddings show 99% cosine similarity for unrelated code. Is your vector search broken?
Testing: Understanding of Transformer representation degeneration (BERT Anisotropy Problem).
That is the well-documented Representation Degeneration Problem in BERT models. Pre-trained embeddings occupy a narrow cone in high-dimensional vector space, skewing raw cosine scores above 0.85 even for different functions. In search.py, we implemented a calibrated piecewise linear transformation that remaps the active 0.70–0.99 anisotropic cluster into a realistic 50%–99% spread, restoring meaningful differentiation.

Why SimpleGate ($X_1 \odot X_2$) Matters

Standard neural networks rely on non-linear activation functions like ReLU or GELU. In medical imaging, ReLU clips negative gradients, which can erase subtle negative residual noise vectors and cause blotchy artifacts.

class SimpleGate(nn.Module): def forward(self, x): # Channel splitting: [B, C, H, W] -> two [B, C/2, H, W] x1, x2 = x.chunk(2, dim=1) return x1 * x2 # Element-wise multiplication provides non-linearity

SimpleGate provides continuous self-attention gating equivalent to a Gated Linear Unit (GLU) without evaluating transcendental sigmoid functions, completely eliminating activation latency on edge clinic CPUs.

The "Rule of 16" Reflection Padding Pipeline

NAFNet utilizes a 4-level U-Net hierarchy. Because the feature map dimensions are halved at each downsampling transition ($2^4 = 16$), input dimensions must be strictly divisible by 16.

If an uploaded radiograph has odd dimensions (e.g. 1021×1021), integer floor division in PyTorch causes dimension mismatches during decoder skip-connection concatenation ($1021 \to 510.5 \to 255.25 \to \dots$).

def pad_to_multiple(tensor, multiple=16): _, _, h, w = tensor.shape pad_h = (multiple - h % multiple) % multiple pad_w = (multiple - w % multiple) % multiple # Reflection mode avoids artificial black halos return F.pad(tensor, (0, pad_w, 0, pad_h), mode="reflect"), h, w

Client-Side Canvas Downscaling & MD5 Caching

  • Edge Preprocessing: Modern diagnostic flat-panel detectors generate 40-Megapixel images (8000×6000). To protect server GPU VRAM and prevent network saturation, client-side HTML5 Canvas scales the longest side to 1024px, ensuring uploads stay under 5 MB.
  • Deterministic MD5 Caching: FastAPI checks an MD5 hash of (image_bytes + model + sigma). Repeated clinical uploads return cached results in <20ms with zero redundant GPU compute.
  • Non-Blocking Tasks: Long-running forward passes are dispatched to BackgroundTasks while the React client polls via a lightweight 1.5s hook, preventing HTTP 504 gateway timeouts.

Senior Defense 01 Could your model hallucinate false anatomy or erase hairline fractures?
Testing: Clinical safety awareness and hallucination risk in generative vs residual models.
Generative models (like GANs or Diffusion models) suffer from hallucination risks because they sample from latent priors. DenoiseRX is strictly a deterministic residual regressor: y = x + f(x). It does not synthesize high-frequency textures from noise; it acts strictly as a spatially constrained non-linear noise subtraction filter. Furthermore, our SSIM score of 0.9251 proves high-contrast bone margins remain uncorrupted.
Senior Defense 02 Your model was trained on synthetic Gaussian noise. Real X-rays have Poisson quantum mottle. Is this clinically viable?
Testing: Understanding of medical physics vs machine learning simplifications.
Physical quantum mottle follows a Poisson distribution at the photon detection level, compounded by Gaussian read noise in flat-panel CMOS arrays. In computer vision literature, zero-mean Gaussian perturbation (σ=25/255) is the standard benchmark proxy when hardware low-dose pairs are unlabelled. For hospital deployment, the pipeline would be fine-tuned on physical phantom pairs or calibrated using Anscombe variance-stabilizing transformations.

Heuristic 1: Star Coordinator Detection

Pump organizers blast instructions outwards across social media to maximize retail FOMO without participating in organic two-way conversations.

# Directional asymmetry out-degree ratio ratio = out_deg / (out_deg + in_deg) if out_deg >= 10 and ratio >= 0.8: emit_alert("STAR_TOPOLOGY", user)

Raw out-degree alone flags organic news outlets. The ratio $\frac{\text{deg}^+}{\text{deg}^+ + \text{deg}^-}$ measures extreme directional asymmetry (≥ 0.8).

Heuristic 2: Pseudo-Clique Bot Rings

Fraud syndicates deploy bot swarms that retweet and reply to each other in dense clusters to manipulate social recommendation algorithms.

# Edge density over candidate subgraph S possible_edges = n * (n - 1) / 2 density = internal_edges / possible_edges if len(S) >= 5 and density >= 0.6: emit_alert("CLIQUE_DETECTED", cluster)

Real bot networks experience network jitter, rarely forming perfect 1.0 cliques. A 0.6 density threshold is noise-tolerant while running in polynomial time.

Senior Defense 01 Calling batch_df.collect() pulls data to the driver node. Isn't that an anti-pattern in Spark?
Testing: Distributed Big Data architecture fundamentals & honesty about bottlenecks.
Yes, in general distributed Big Data architecture, calling .collect() is an anti-pattern because it centralizes data onto the driver node, bypassing executor parallelism and risking Driver OOM. In this architecture, it represents a conscious prototyping trade-off: our 10-second micro-batches contain thousands of edges, easily fitting into memory. For 100x scale, the correct architectural evolution is to eliminate .collect() and execute distributed motif finding using Spark GraphFrames across worker executors.
Senior Defense 02 What happens if fraudsters space out their messages across 15 seconds instead of 10?
Testing: Understanding windowing boundaries and edge-splitting in stream processing.
This is the classic tumbling window boundary problem. If an attack is split across second 8 and second 12, non-overlapping 10-second micro-batches divide the edges, potentially dropping measured density below the 0.6 threshold. The production evolution is to replace tumbling micro-batches with a stateful sliding window (e.g. a 60-second window evaluated every 10 seconds) using Spark Structured Streaming watermarks.
